# Диагностика

| Симптом | Что делать |
|---|---|
| `Not logged in · Please run /login` | Выполните `claude auth login`. |
| `401 Invalid API key` | В окружение просочился ключ родителя — проверьте `passEnv`, там не должно быть `ANTHROPIC_API_KEY`. |
| `project_dir вне белого списка` | Добавьте путь в `allowedRoots`. В JSON слэши экранируются: `"D:\\Projects"`. |
| `не удалось запустить "claude"` | Claude Code нет в PATH — укажите полный путь в `claudeBin`. |
| `404 … Модель недоступна или не существует` | Опечатка в параметре `model` вызова либо в поле `model` конфига, или у аккаунта нет доступа к этой модели. |
| `недопустимое имя модели` | Значение `model` не прошло проверку схемы: допустимы буквы, цифры и `. _ : - [ ]`, начинаться должно с буквы или цифры. |
| `claudeBin указывает на .cmd-обёртку` | Укажите `.exe`, например `C:\Users\<имя>\.local\bin\claude.exe`. |
| `достигнут предел одновременных задач` | Дождитесь задач или увеличьте `maxConcurrent`. |
| Задача не найдена в `get_task_status` | Сервер перезапускался либо истёк `jobRetentionMs`. История — в логе. |
| `status: "timeout"` | Увеличьте `timeoutMs`. |
| `execute_task` требует `session_id` | Выполнение «с нуля» запрещено. Начните с `plan_task`. |
| `план … получен, но не одобрен` | Пропущен шаг `approve_plan`. |
| `сессия … не проходила согласование` | `session_id` чужой, либо сервер перезапускался, либо истёк `sessionRetentionMs`. Пройдите цикл заново. |
| `plan_digest не совпадает` | Возьмите `plan_digest` из последнего ответа `plan_task` — после переплана он меняется. |
| `план … содержит открытые вопросы` | Модели не хватило данных. Прочтите раздел «Открытые вопросы» в `result_text`, уточните их у пользователя и вызовите `plan_task` заново. |
| `план … уже выполнен` | Одобрение израсходовано. Для новой работы нужен новый `plan_task`. |
| `по сессии … уже идёт выполнение` | Дождитесь результата или снимите задачу через `cancel_task`. |
| `план строился для каталога …` | `project_dir` должен совпадать с тем, для которого планировали. |
| `path выходит за пределы project_dir` | `path` в файловых инструментах — относительный путь внутри проекта, без `../`. |
| `path должен быть относительным путём` | Передан абсолютный путь. Оставьте только часть после `project_dir`. |
| `path не является обычным файлом` | Указан каталог или устройство. Файловые инструменты работают с обычными файлами. |
| `файл не найден` | Путь считается от `project_dir`, а не от текущего каталога. Пустой файл читается штатно — это именно отсутствие файла. |
| `путь не найден` | То же для `list_project_files`. Пустой список означал бы другое: каталог есть, но всё в нём отфильтровано. Если каталог точно есть — возможно, опечатка в регистре. |
| `path не является файлом или каталогом` | Указан сокет, fifo или устройство. Листинг работает с обычными файлами и каталогами. |
| `паттерн-отрицание в ignore не поддерживается` | Уберите `!` из `ignore`: перечислите то, что нужно скрыть, либо сузьте область через `path`. Чтобы увидеть скрытое, используйте `use_gitignore: false`. |
| Листинг не показывает нужный файл | Он скрыт правилом игнора. Повторите с `use_gitignore: false` или `use_default_ignores: false`, либо укажите его каталог в `path` — явно запрошенный путь под игнор не подпадает. |
| `файл … слишком большой` | Больше `maxFileBytes`. Поднимите лимит либо работайте через `plan_task`/`execute_task`. |
| `похоже на бинарный файл` | Файловые инструменты только для текста, base64 они не отдают. |
| `git не найден` | Claude Desktop иногда даёт урезанный PATH — укажите полный путь в `gitBin` (или через `CCC_GIT_BIN`). Проверьте строку `startup` с `component: "git"` в логе — она пишется при запуске. |
| `не git-репозиторий` | `project_dir` для `run_git` должен быть корнем репозитория (там, где лежит `.git`), не подкаталогом. |
| `недопустимое имя ветки` | Разрешены латиница, цифры, точка, дефис, подчёркивание и слэш; первый символ — буквенно-цифровой. |
| `параметр … не применим к операции` | У каждой `operation` свой набор параметров; лишний или недостающий — ошибка вызова. |
| `дифф обрезан по лимиту maxDiffBytes` | Не ошибка: сузьте `path` или запросите `stat: true`. Либо поднимите `maxDiffBytes`. |
| `claude native binary not installed` | npm-установка без postinstall. Переставьте нативным установщиком, `claudeBin` — `~/.local/bin/claude`. |
| `expected record, received array` | В `claude_desktop_config.json` ключ `mcpServers` должен быть объектом по имени сервера, а не массивом. |
| Блок `mcpServers` пропал сам | Файл правили при запущенном приложении — оно записало свою копию при выходе. Править только после ⌘Q. |
| `403 … does not support model …` | Модель из `~/.claude/settings.json` недоступна headless-режиму — задайте рабочую в `model`. |
| `Credit balance is too low` | CLI авторизован аккаунтом без подписки. Проверьте `claude auth status` (поле `subscriptionType`) и перелогиньтесь. |
| `progress.bad_lines > 0`, а `result_text` пуст | Формат `stream-json` дочернего CLI разошёлся с ожиданиями моста. `hint` в этом случае уже говорит об этом прямо. Обход — `streamEvents: false` в конфиге: мост попросит у CLI один итоговый JSON вместо потока. |
| Записи `stream_warn` в логе | Разбор потока идёт с ошибками: `unparseable` — строка не разобралась (дрейф формата), `too_long` — строка сверх предела длины, `no_result_line` — процесс закончился без итоговой строки `result`. Одна запись на класс на процесс; количество — в `progress.bad_lines`/`oversize_lines`. |
| `progress` пустой у идущей задачи | Либо `streamEvents: false` (тогда это норма), либо CLI не поддерживает `stream-json`. Проверьте `progress.streaming` и записи `stream_warn`. |
| `unknown_event_types` непустой | CLI начал слать типы событий, которых мост не знает. Само по себе не ошибка — счётчик нужен, чтобы дрейф формата был заметен заранее. |
