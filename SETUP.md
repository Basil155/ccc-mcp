# ccc-mcp (Command Claude Code): настройка, запуск и использование

Пошаговое руководство оператора. Обзор моста — в [README.md](README.md), протокол и поля ответа —
в [docs/protocol.md](docs/protocol.md), готовый протокол для вызывающего ИИ-агента —
в [AGENT-PROTOCOL.md](AGENT-PROTOCOL.md).

---

## 1. Авторизация Claude Code (один раз)

Мост не хранит и не передаёт учётные данные: дочерний процесс `claude` аутентифицируется сам.
Более того, мост специально вычищает `ANTHROPIC_*` и `CLAUDE_*` из окружения, чтобы ключ
родительского процесса до него не доходил.

```bash
claude auth login
```

Проверка — в ответе должно быть `"is_error":false`:

```bash
claude -p "hi" --output-format json
```

Если видите `Not logged in · Please run /login` — авторизация не выполнена, и любой вызов моста
вернёт ту же ошибку.

---

## 2. Сборка

```bash
npm install
```

```bash
npm run build
```

Результат — `dist/index.js`. Пересобирать нужно после каждого изменения в `src/`.

## 3. Конфиг сервера

Без конфига сервер **намеренно не стартует**: нет белого списка каталогов — нет работы
(fail-closed).

```bash
cp ccc-mcp.config.example.json ccc-mcp.config.json
```

Затем впишите в `allowedRoots` свои каталоги. Рабочий конфиг в репозиторий не попадает —
он в `.gitignore`, потому что содержит пути конкретной машины.

Где сервер ищет конфиг, по порядку:

1. путь из переменной `CCC_MCP_CONFIG`;
2. `ccc-mcp.config.json` рядом с пакетом;
3. `ccc-mcp.config.json` в текущем каталоге.

В конфиге разрешены комментарии `//` и `/* … */`.

### Что стоит настроить

| Ключ | Значение по умолчанию | Когда менять |
|---|---|---|
| `allowedRoots` | — (обязателен) | Главная настройка безопасности. Список абсолютных путей, внутри которых мосту разрешено работать |
| `defaultWaitSeconds` | `20` | Сколько ждать результат до ухода в фон. Держите заметно ниже таймаута MCP-клиента (обычно ~60 с) |
| `timeoutMs` | `1800000` (30 мин) | Если задачи бывают длиннее |
| `maxConcurrent` | `3` | Сколько процессов `claude` разрешено одновременно |
| `sessionRetentionMs` | `86400000` (сутки) | Срок жизни плана и одобрения |
| `jobRetentionMs` | `3600000` (час) | Сколько завершённых задач доступно через `get_task_status` |
| `logResultText` | `false` | `true`, если нужны тексты отчётов в логе. На файловые инструменты не влияет: ни содержимое файлов, ни список путей в лог не пишутся никогда |
| `maxFileBytes` | `524288` (512 KiB) | Предел размера файла для `read_project_file`/`write_project_file`. Один лимит на чтение и запись |
| `maxListEntries` | `2000` | Предел числа записей в ответе `list_project_files`. Превышение не ошибка — придёт частичный список с `truncated: true`. Поднимайте, если проект действительно больше |
| `claudeBin` | `"claude"` | Полный путь к бинарю, если его нет в `PATH`. На macOS нативная установка кладёт его в `~/.local/bin/claude` |
| `gitBin` | `"git"` | Полный путь к `git`, если его нет в `PATH`. Дефолт обычно работает даже с урезанным PATH от Claude Desktop, но при промахе инструмент `run_git` иначе не починить |
| `maxDiffBytes` | `262144` (256 KiB) | Предел объёма вывода git, прежде всего для `diff` у `run_git`. Превышение не ошибка — придёт частичный патч с `truncated: true` |
| `gitTimeoutMs` | `120000` (2 мин) | Таймаут одной git-операции. Две минуты, потому что `git commit` запускает pre-commit хуки репозитория, которые могут линтовать проект |
| `model` | — (решает CLI) | Модель по умолчанию для дочернего `claude`. Задайте явно, если модель из `~/.claude/settings.json` недоступна headless-режиму — такой вызов падает с 403 ещё до начала работы. Отдельный вызов может переопределить её параметром `model` в `plan_task`/`execute_task` |
| `sandbox` | `"auto"` | Не трогайте: флага `--sandbox` в текущих версиях CLI нет, `auto` включит его сам, когда появится |
| `streamEvents` | `true` | Килсвитч разбора потока событий. `false` — если дочерний CLI перестал отдавать разбираемый `stream-json`: мост вернётся к `--output-format json`, `progress` станет пустым, остальные поля отчёта не изменятся. Переключается `CCC_STREAM_EVENTS=0` |
| `logProgress` | `false` | `true` — писать в лог периодическую сводку живого состояния задачи. Это телеметрия, а не аудит: счётчики и имена инструментов, без текста модели. Для разбора одной задачи обычно хватает сводки в записи `finish`/`cancel` — она пишется всегда, без флага |
| `logProgressIntervalMs` | `60000` (1 мин) | Не чаще одной записи прогресса в этот интервал на задачу. Для 40-минутного прогона это ~40 строк |
| `hooksEnabled` | `false` | `true` — включить пооперационные разрешения (см. ниже). Экспериментально: сначала проверьте механизм вручную |
| `sensitiveTools` | `["Bash", "Write", "Edit"]` | Какие инструменты дочернего CLI требуют одобрения. Для реальных задач практичнее `["Bash"]` |
| `retryBudget` | `10` | Сколько отказов выдержит один и тот же вызов, прежде чем запретится до конца задачи |
| `maxPendingRequests` | `50` | Предел числа различных запросов на разрешение в одной задаче |
| `allowWaitCommand` | `true` | Пропускать ли синхронный `sleep N` (N ≤ 60) без одобрения — пауза, чтобы модель дождалась решения. Тот же `sleep` с `run_in_background: true` требует одобрения: он возвращается мгновенно и ждать модель не заставляет. Это разрешение моста, а не гарантия: там, где `sleep` в `Bash` запрещён политикой самого CLI, модель ждёт другим способом |
| `autoApproveCommands` | `[]` | Команды `Bash`, проходящие без одобрения, — чтобы не подтверждать вручную десятки одинаковых `npm run typecheck` за прогон. Сравнение по **всей строке целиком** (пробелы по краям отбрасываются, внутренние — нет): `npm run typecheck && rm -rf /` не подпадает под `npm run typecheck`. Класть сюда стоит только детерминированные проверки, не тратящие деньги и не ходящие в сеть; `npm run smoke` без `--no-live` под это не подходит — он порождает дочерние процессы `claude`. Автоодобренный вызов в `permission_requests` не появляется, его след — строка лога с `"decision": "auto_allowed"` |

Переменные окружения перекрывают файл: `CCC_ALLOWED_ROOTS` (несколько путей через `;`),
`CCC_CLAUDE_BIN`, `CCC_GIT_BIN`, `CCC_MODEL`, `CCC_TIMEOUT_MS`, `CCC_LOG_FILE`,
`CCC_HOOKS_ENABLED` (`1`/`0`), `CCC_STREAM_EVENTS` (`1`/`0`), `CCC_AUTO_APPROVE_COMMANDS`
(несколько команд через `;`).

> Примеры путей в этом разделе и в образце конфига — Windows-овые. На macOS/Linux пути
> обычные POSIX-овые, экранировать в JSON ничего не нужно: `"/Users/<имя>/Projects"`.

## 4. Подключение к Claude

### Вариант А — Claude Code CLI

```bash
claude mcp add --scope user ccc-mcp -e CCC_MCP_CONFIG=D:/Projects/ccc-mcp/ccc-mcp.config.json -- node D:/Projects/ccc-mcp/dist/index.js
```

> Имя сервера (`ccc-mcp`) обязано идти **до** `-e`: этот флаг вариадический и иначе заберёт
> имя себе, отвалившись с `Invalid environment variable format`.

Проверить, что сервер зарегистрирован и отвечает:

```bash
claude mcp list
```

### Вариант Б — Claude Desktop (Windows)

Файл настроек на Windows: `%APPDATA%\Claude\claude_desktop_config.json`
(то есть `C:\Users\<имя>\AppData\Roaming\Claude\claude_desktop_config.json`).

Добавьте секцию `mcpServers` на верхнем уровне, **сохранив** уже существующие ключи:

```jsonc
{
  "coworkUserFilesPath": "...",
  "preferences": { /* оставить как есть */ },

  "mcpServers": {
    "ccc-mcp": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["D:\\Projects\\ccc-mcp\\dist\\index.js"],
      "env": {
        "CCC_MCP_CONFIG": "D:\\Projects\\ccc-mcp\\ccc-mcp.config.json"
      }
    }
  }
}
```

Затем **полностью закройте приложение** (через иконку в трее, а не крестиком в окне) и запустите
заново: конфиг читается только при старте.

> **Указывайте абсолютный путь к `node.exe`, а не просто `"node"`.** Claude Desktop запускается
> из проводника и наследует не то окружение, что ваш терминал; «сервер не поднялся» на Windows
> чаще всего означает именно ненайденный `node`. Проверить свой путь: `where node`.

> В JSON обратные слэши экранируются (`\\`). В командах оболочки удобнее прямые слэши —
> Node понимает их на Windows одинаково.

Проверить, что команда из конфига рабочая, можно не дожидаясь перезапуска — сервер должен
напечатать две строки и остаться висеть:

```bash
CCC_MCP_CONFIG="D:\Projects\ccc-mcp\ccc-mcp.config.json" "C:\Program Files\nodejs\node.exe" "D:\Projects\ccc-mcp\dist\index.js"
```

### Вариант В — macOS

Установка самого CLI — нативным установщиком:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Он кладёт бинарь в `~/.local/bin/claude` и самообновляется. npm-вариант (`npm i -g
@anthropic-ai/claude-code`) тоже работает, но ломается, если в npm-конфиге стоит
`--ignore-scripts` или `--omit=optional`: postinstall не скачает нативный бинарь, и на месте
`claude` останется заглушка, печатающая `Error: claude native binary not installed.`

> **Абсолютные пути обязательны — и для `node`, и для `claudeBin`.** GUI-приложение запускается
> из Finder и не наследует PATH из `~/.zshrc`, так что ни `/opt/homebrew/bin`, ни `~/.local/bin`
> в его окружении может не оказаться. Свои пути: `which node`, `which claude`.

#### Для Claude Code

Как в варианте А, но пути абсолютные:

```bash
claude mcp add --scope user ccc-mcp -e CCC_MCP_CONFIG=/Users/<имя>/Projects/ccc-mcp/ccc-mcp.config.json -- /opt/homebrew/bin/node /Users/<имя>/Projects/ccc-mcp/dist/index.js
```

```bash
claude mcp list
```

Должно напечатать `ccc-mcp: … - ✔ Connected`. Инструменты подхватываются при старте сессии, так
что уже открытую сессию нужно перезапустить.

#### Для Claude Desktop

Файл: `~/Library/Application Support/Claude/claude_desktop_config.json`. Форма та же, что на
Windows, — `mcpServers` это объект, где ключ есть имя сервера:

```json
{
  "mcpServers": {
    "ccc-mcp": {
      "command": "/opt/homebrew/bin/node",
      "args": ["/Users/<имя>/Projects/ccc-mcp/dist/index.js"],
      "env": {
        "CCC_MCP_CONFIG": "/Users/<имя>/Projects/ccc-mcp/ccc-mcp.config.json"
      }
    }
  }
}
```

> **Правьте файл только при полностью закрытом приложении (⌘Q).** Приложение держит конфиг
> в памяти и записывает свою копию при выходе — правка «на живую» будет затёрта молча, без
> единой строки в логах, и выглядит это так, будто ключ не поддерживается.

> **Массив вместо объекта приложение не примет.** Оно откажется читать весь файл целиком
> с диалогом `expected record, received array`.

Диалог **Add custom connector** здесь не поможет: он умеет только удалённые серверы по HTTPS.
Поля Command / Arguments / Environment показываются лишь у записи, у которой транспорт уже
`stdio`, то есть только при редактировании созданной файлом.

Проверка после перезапуска — `~/Library/Logs/Claude/mcp-server-ccc-mcp.log`. Если сервер
поднялся, там будет `Server started and connected successfully` и две строки баннера самого
моста.

## 5. Проверка

Быстрая, без обращений к API и без трат токенов:

```bash
node scripts/smoke.mjs --no-live
```

Полная, с реальными вызовами Claude Code — проходит весь протокол, включая отказы:

```bash
node scripts/smoke.mjs
```

Сервер при старте печатает в stderr версию CLI, поддержку `--sandbox`, число корней и путь
к конфигу — по этой строке удобно убеждаться, что подхватился нужный файл.

## 6. Использование из агента

Мост навязывает протокол, и вызывающий агент должен его знать — иначе будет упираться в отказы.

```
plan_task  →  показать план человеку  →  approve_plan  →  execute_task
```

Полный протокол для вызывающего агента — императивно, в форме, готовой к вставке в системный
промпт или в `CLAUDE.md` целевого проекта — вынесен отдельным файлом:
[AGENT-PROTOCOL.md](AGENT-PROTOCOL.md). Там же работа с файловыми инструментами и `run_git`
вне протокола, поведение при долгих задачах и антипаттерны.

Если включены пооперационные разрешения (`hooksEnabled: true`), агенту добавляется работа с
`permission_requests` — механизм описан в [docs/permissions.md](docs/permissions.md), порядок
действий агента — в том же `AGENT-PROTOCOL.md`. По умолчанию выключено, и тогда
`permission_requests` всегда приходит пустым.

## 7. Диагностика

Лог всех вызовов — JSONL рядом с конфигом (`logs/ccc-mcp.jsonl`). В нём видна вся цепочка:
`start`, `approve`, `denied`, `finish`, `timeout`, `cancel`, а при включённых хуках — ещё
`hook` и `permission`. Файловые инструменты пишут `file_read` и `file_write` — с путём, размером
и `sha256`, но без содержимого. `run_git` пишет `git_op` — операцию, код возврата и счётчики, без
диффов и списков путей. Секреты вырезаются при записи.

| Сообщение | Что делать |
|---|---|
| `не удалось запустить "claude"` | Указать полный путь в `claudeBin` |
| `claudeBin указывает на .cmd-обёртку` | Windows: указать `.exe`, например `C:\Users\<имя>\.local\bin\claude.exe` |
| `claude native binary not installed` | npm-установка без postinstall. Переставить нативным установщиком, `claudeBin` — `~/.local/bin/claude` |
| `git не найден` | Указать полный путь в `gitBin` (или переменной `CCC_GIT_BIN`). Проверьте строку `startup` с `component: "git"` в логе — она пишется при запуске |
| `expected record, received array` | В `claude_desktop_config.json` ключ `mcpServers` должен быть объектом по имени сервера, а не массивом |
| Блок `mcpServers` пропал сам | Файл правили при запущенном приложении — оно записало свою копию при выходе. Править только после ⌘Q |
| `403 … does not support model …` | Модель из `~/.claude/settings.json` недоступна headless-режиму — задать рабочую в `model` |
| `Credit balance is too low` | CLI авторизован аккаунтом без подписки. Проверить `claude auth status` (поле `subscriptionType`) и перелогиниться |

Это только типовые ошибки установки и подключения. Полный справочник симптомов — отказы
протокола, файловых инструментов, `run_git`, лимитов и таймаутов — в
[docs/troubleshooting.md](docs/troubleshooting.md).

### Если сервер вообще не появляется в списке инструментов

1. Запустите его вручную — он должен напечатать две строки в stderr и остаться висеть:
   `CCC_MCP_CONFIG=<путь> node dist/index.js`
2. Убедитесь, что `dist/index.js` собран (`npm run build`).
3. Проверьте, что путь в `args` абсолютный и слэши в JSON экранированы.
4. Перезапустите Claude — конфиг читается при старте.
