# CLAUDE.md — ccc-mcp (Command Claude Code)

Инструкции для Claude Code, работающего в этом репозитории через мост `ccc-mcp`
(`plan_task`/`execute_task`).

Этот файл — про работу **над** репозиторием `ccc-mcp`. Протокол для агента, который
**использует** мост как инструмент в своём проекте, — в [AGENT-PROTOCOL.md](AGENT-PROTOCOL.md).

## Канонические команды проверки

Мост поддерживает `autoApproveCommands` — список Bash-команд, пропускаемых
без ручного одобрения оператора. Совпадение **точное, посимвольное**: любое
отличие в обёртке (другой `tail -N`, добавленный `echo $?`, другой пайп)
превращает команду в новую строку, которая уже не совпадает со списком и
требует обычного одобрения.

Чтобы автоодобрение реально работало, используй эти три команды **ровно в
таком виде**, без импровизации над обёрткой:

```bash
npm run typecheck 2>&1 | tail -20
npm run build 2>&1 | tail -20
npm run smoke -- --no-live 2>&1 | tail -60
```

Не добавляй `&& echo "EXIT=$?"`, не меняй число строк в `tail`, не оборачивай
в `; echo "done"` — любая из этих модификаций уводит команду из списка
автоодобрения и заставляет оператора одобрять её вручную, хотя смысл вызова
не изменился.

Если нужно посмотреть конкретную часть вывода (конкретный тест, конкретную
секцию) — сначала прогони одну из канонических команд целиком, потом
дополнительно `grep`/`sed` уже готовый вывод отдельным вызовом. Не встраивай
фильтрацию в первый вызов: `npm run typecheck 2>&1 | tail -20` — да,
`npm run typecheck 2>&1 | grep -i error` — нет (это уже другая, неодобренная
строка).

## Пишущий git

`git commit`, `git push` и любые другие операции, меняющие состояние
репозитория, в `autoApproveCommands` никогда не попадут — используй
инструмент `run_git` моста вместо `git` через Bash, он не требует
одобрения оператора вовсе (работает вне протокола хуков) и не тратит
попытки `retryBudget`.

## Живой `npm run smoke` (без `--no-live`)

Никогда не проси автоодобрения на `npm run smoke` без `--no-live` — эта
команда порождает дочерние процессы `claude` и тратит деньги пользователя.
Она сознательно не входит и не должна попадать в `autoApproveCommands`.
Каждый такой прогон требует явного разрешения оператора.
